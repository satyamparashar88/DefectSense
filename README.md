# DefectSense — PCB Defect Detection

**An AI-powered PCB inspection system using RF-DETR Nano, FastAPI, Streamlit, and Docker.**

DefectSense is a computer vision project designed to detect and visualize defects on printed circuit boards (PCBs). It combines a fine-tuned RF-DETR Nano model with a web interface that allows users to upload PCB images, inspect predicted defects, and review confidence scores and inspection summaries.

The project was developed as a portfolio MVP to explore deep learning, computer vision, model evaluation, API development, and containerized application deployment.

## Key Features

* **AI-based defect detection:** Uses a fine-tuned RF-DETR Nano checkpoint.
* **Six defect classes:** Open, short, mousebite, spur, copper, and pin-hole.
* **Image-based inspection:** Upload a PCB image through the Streamlit interface.
* **Visual predictions:** Display detected defects with bounding boxes and confidence scores.
* **Inspection summaries:** View defect counts and a summary generated by the decision engine.
* **REST API:** Serve predictions through a FastAPI backend.
* **Docker support:** Run the frontend and backend using Docker Compose.
* **Model evaluation:** Includes scripts for evaluation, benchmarking, and dataset preparation.

## Supported Defect Classes

The model is configured to recognize these six PCB defect categories:

| Class ID | Defect    |
| -------: | --------- |
|        0 | Open      |
|        1 | Short     |
|        2 | Mousebite |
|        3 | Spur      |
|        4 | Copper    |
|        5 | Pin-hole  |

Predictions depend on the quality of the input image, the trained checkpoint, and the selected confidence threshold. This project is an experimental inspection aid, not a replacement for validated industrial quality-control systems.

## Model Evaluation

RF-DETR Nano was fine-tuned for 20 epochs and evaluated on a test set of 500 images.

| Metric    | Result |
| --------- | -----: |
| mAP@50:95 | 70.35% |
| mAP@50    | 93.46% |
| mAP@75    | 82.10% |
| Precision | 79.26% |
| Recall    | 93.57% |
| F1 score  | 85.82% |
| mAR@100   | 78.10% |

These results reflect the evaluation run performed during development. They are not a guarantee of performance on other datasets or real-world production images.

A YOLOv8 model was also evaluated as a baseline. Its checkpoint is kept separately from the public repository.

## Getting Started with Docker

### Prerequisites

Install the following software:

* [Docker Desktop](https://www.docker.com/products/docker-desktop/)
* [Git](https://git-scm.com/downloads)

Start Docker Desktop before running the application.

### 1. Clone the repository

```bash
git clone https://github.com/satyamparashar88/DefectSense.git
cd DefectSense
```

### 2. Add the trained model checkpoint

The trained RF-DETR checkpoint is not included in this repository. Obtain the checkpoint through an authorized source and place it at:

```text
models/rf_detr_best_ema.pth
```

The application expects this exact filename. The DeepPCB dataset and the YOLOv8 baseline checkpoint are also excluded from the repository.

### 3. Build and start the application

From the project root, run:

```bash
docker compose up --build
```

The first build downloads the required dependencies and may take several minutes.

### 4. Open the application

Once both services are running, open these addresses in your browser:

* **Streamlit application:** http://localhost:8501
* **FastAPI documentation:** http://localhost:8000/docs
* **Backend health check:** http://localhost:8000/health

Upload a PCB image in the frontend to view the predicted defects, confidence scores, annotated image, and inspection summary.

### 5. Stop the application

Press `Ctrl+C` in the terminal, then run:

```bash
docker compose down
```

## Dataset and Model Files

The project was developed using the DeepPCB dataset. Dataset files and trained model checkpoints are intentionally not committed to this repository to avoid uploading large binary files and to keep the repository focused on source code.

To reproduce training or evaluation, obtain the dataset and required checkpoints from sources you are authorized to use, then follow the scripts and configuration provided in the repository.

## Security and Limitations

* The application is intended for local development and portfolio demonstration.
* Do not expose the API publicly without reviewing authentication, request limits, upload-size restrictions, and other deployment security controls.
* Model predictions can include false positives and false negatives.
* Reproducing the reported evaluation metrics requires the relevant dataset, checkpoint, and evaluation setup.
* Review the applicable licenses for the model, dependencies, dataset, and any checkpoint before redistribution or commercial use.
